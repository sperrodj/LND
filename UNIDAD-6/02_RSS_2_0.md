# 2. RSS 2.0

## 2.1. ¿Qué es RSS?

RSS es una familia de formatos de sindicación. En esta unidad utilizaremos **RSS 2.0**, una versión ampliamente reconocida y basada en XML.

Un documento RSS 2.0 contiene:

```text
rss
└── channel
    ├── información general
    ├── item
    ├── item
    └── ...
```

- `rss` es el elemento raíz.
- `channel` representa el canal.
- `item` representa cada publicación.

## 2.2. Estructura mínima

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>Letras del Atlántico</title>
    <link>https://example.com/</link>
    <description>
      Reseñas, entrevistas y novedades del mundo editorial.
    </description>
  </channel>
</rss>
```

Los tres elementos obligatorios de `channel` son:

| Elemento | Función |
|---|---|
| `title` | Nombre del canal |
| `link` | URL del sitio asociado |
| `description` | Descripción general |

El atributo `version="2.0"` identifica la versión de RSS.

## 2.3. Primer canal con publicaciones

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>Letras del Atlántico</title>
    <link>https://example.com/</link>
    <description>
      Reseñas, entrevistas y novedades del mundo editorial.
    </description>
    <language>es-ES</language>

    <item>
      <title>Diez novelas para descubrir la fantasía contemporánea</title>
      <link>https://example.com/reportajes/fantasia-contemporanea</link>
      <description>
        Una selección de obras recientes para ampliar nuestra lista de lecturas.
      </description>
    </item>

    <item>
      <title>Entrevista con una autora canaria</title>
      <link>https://example.com/entrevistas/autora-canaria</link>
      <description>
        Conversamos sobre escritura, publicación y literatura insular.
      </description>
    </item>
  </channel>
</rss>
```

## 2.4. Elementos habituales de `channel`

### `language`

Indica el idioma principal:

```xml
<language>es-ES</language>
```

### `copyright`

```xml
<copyright>© 2026 Letras del Atlántico</copyright>
```

### `managingEditor`

```xml
<managingEditor>redaccion@example.com (Redacción)</managingEditor>
```

### `webMaster`

```xml
<webMaster>soporte@example.com (Equipo técnico)</webMaster>
```

### `pubDate`

Fecha de publicación del canal:

```xml
<pubDate>Wed, 18 Nov 2026 10:00:00 +0000</pubDate>
```

### `lastBuildDate`

Momento de la última generación del canal:

```xml
<lastBuildDate>Wed, 18 Nov 2026 12:30:00 +0000</lastBuildDate>
```

### `generator`

```xml
<generator>Generador propio de LND</generator>
```

### `docs`

```xml
<docs>https://www.rssboard.org/rss-specification</docs>
```

### `ttl`

Indica durante cuántos minutos puede almacenarse el canal antes de volver a consultarlo:

```xml
<ttl>60</ttl>
```

No garantiza que todos los lectores respeten exactamente ese intervalo.

## 2.5. Imagen del canal

```xml
<image>
  <url>https://example.com/img/logo.png</url>
  <title>Letras del Atlántico</title>
  <link>https://example.com/</link>
  <width>144</width>
  <height>144</height>
</image>
```

Dentro de `image`, los elementos fundamentales son:

- `url`: dirección de la imagen.
- `title`: texto alternativo o título.
- `link`: destino al pulsarla.

## 2.6. Elementos de `item`

### `title`

```xml
<title>Reseña de La ciudad y sus muros inciertos</title>
```

### `link`

```xml
<link>https://example.com/resenas/la-ciudad-y-sus-muros-inciertos</link>
```

### `description`

```xml
<description>
  Comentamos los temas, la estructura y el estilo de la novela.
</description>
```

En un `item` debe existir, como mínimo, `title` o `description`. En la práctica es recomendable incluir ambos.

### `author`

```xml
<author>sara@example.com (Sara Pérez)</author>
```

### `category`

Puede repetirse:

```xml
<category>Literatura japonesa</category>
<category>Análisis</category>
```

Opcionalmente puede indicar el dominio de clasificación:

```xml
<category domain="https://example.com/categorias">
  Análisis
</category>
```

### `comments`

```xml
<comments>
  https://example.com/resenas/la-ciudad-y-sus-muros-inciertos#comentarios
</comments>
```

### `pubDate`

```xml
<pubDate>Wed, 18 Nov 2026 09:30:00 +0000</pubDate>
```

### `guid`

Identifica de forma estable una publicación:

```xml
<guid isPermaLink="false">
  letras-2026-resena-001
</guid>
```

Si su contenido es una URL permanente:

```xml
<guid isPermaLink="true">
  https://example.com/resenas/la-ciudad-y-sus-muros-inciertos
</guid>
```

Un lector utiliza el identificador para reconocer entradas que ya había descargado. No debe cambiar cada vez que se actualiza el canal.

### `source`

Indica el canal original cuando se reutiliza una publicación:

```xml
<source url="https://example.org/rss.xml">
  Revista Original
</source>
```

## 2.7. Fechas en RSS

RSS utiliza fechas con un formato similar a:

```text
Wed, 18 Nov 2026 09:30:00 +0000
```

Partes:

```text
Wed,        → día de la semana
18          → día
Nov         → mes abreviado en inglés
2026        → año
09:30:00    → hora
+0000       → zona horaria
```

Ejemplo para Canarias en horario estándar:

```xml
<pubDate>Wed, 18 Nov 2026 09:30:00 +0000</pubDate>
```

La fecha debe representar un momento real y mantener un formato coherente.

## 2.8. Contenido HTML

### Escapando etiquetas

```xml
<description>
  &lt;p&gt;Nueva reseña con &lt;strong&gt;capturas&lt;/strong&gt;.&lt;/p&gt;
</description>
```

### Utilizando CDATA

```xml
<description><![CDATA[
  <p>Nueva reseña con <strong>capturas</strong>.</p>
  <p>Consulta el artículo completo en nuestra web.</p>
]]></description>
```

CDATA resulta más legible cuando el contenido contiene mucho HTML.

No puede incluirse literalmente la secuencia `]]>` dentro de una sección CDATA.

## 2.9. Contenido multimedia con `enclosure`

`enclosure` enlaza un archivo asociado, como audio, vídeo o imagen:

```xml
<enclosure
  url="https://example.com/audio/episodio-01.mp3"
  length="24576000"
  type="audio/mpeg"/>
```

Sus atributos son:

| Atributo | Función |
|---|---|
| `url` | Dirección absoluta del archivo |
| `length` | Tamaño en bytes |
| `type` | Tipo MIME |

Es especialmente importante en canales de pódcast.

## 2.10. Canal RSS completo

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>Letras del Atlántico</title>
    <link>https://example.com/</link>
    <description>
      Reseñas, entrevistas y novedades del mundo editorial.
    </description>
    <language>es-ES</language>
    <copyright>© 2026 Letras del Atlántico</copyright>
    <lastBuildDate>Wed, 18 Nov 2026 12:30:00 +0000</lastBuildDate>
    <generator>Generador propio de LND</generator>
    <ttl>60</ttl>

    <image>
      <url>https://example.com/img/logo.png</url>
      <title>Letras del Atlántico</title>
      <link>https://example.com/</link>
    </image>

    <item>
      <title>Reseña de La ciudad y sus muros inciertos</title>
      <link>https://example.com/resenas/la-ciudad-y-sus-muros-inciertos</link>
      <description><![CDATA[
        <p>Comentamos los temas, la estructura y el estilo de la novela.</p>
      ]]></description>
      <author>sara@example.com (Sara Pérez)</author>
      <category>Literatura japonesa</category>
      <category>Análisis</category>
      <guid isPermaLink="false">
        letras-2026-resena-001
      </guid>
      <pubDate>Wed, 18 Nov 2026 09:30:00 +0000</pubDate>
    </item>

    <item>
      <title>Novedades editoriales de noviembre</title>
      <link>https://example.com/entrevistas/autora-canaria</link>
      <description>
        Repasamos algunos de los libros publicados durante este mes.
      </description>
      <category>Novedades editoriales</category>
      <guid isPermaLink="false">
        letras-2026-novedades-002
      </guid>
      <pubDate>Tue, 17 Nov 2026 17:00:00 +0000</pubDate>
    </item>
  </channel>
</rss>
```

## 2.11. Errores frecuentes

- Olvidar `version="2.0"`.
- Colocar `item` fuera de `channel`.
- Omitir `title`, `link` o `description` de `channel`.
- Repetir el mismo `guid` en publicaciones diferentes.
- Cambiar el `guid` de una entrada ya publicada.
- Utilizar enlaces relativos.
- Escribir fechas con un formato incorrecto.
- Introducir HTML directamente sin escaparlo ni usar CDATA.
- Confundir la fecha del canal con la fecha de cada entrada.
- Utilizar `&` sin escribir `&amp;`.

2. Añade tres elementos `item`.
3. Incluye dos categorías por entrada.
4. Asigna un `guid` estable a cada publicación.
5. Añade fechas de publicación diferentes.
6. Incluye HTML mediante CDATA en una descripción.
7. Añade una imagen general del canal.
